## 1. 现状一句话

Kotlin + Jetpack Compose 的本地想法记录 App：首页是分组横滑 + 想法卡片，详情页是「小步」列表。数据存 `SharedPreferences` 里的 JSON，图片存 `files/media`，没有网络权限。

### 链接跳转规则

规则表是 `Links.kt` 里的 `RULES`，一条 = 「域名后缀 + 路径正则 + scheme 模板」：

- 模板里 `$1` 取路径正则的第一组，`{q}` 取 `queryKey` 指定的查询参数
- 命中后依次尝试：scheme → 带包名的 https → 普通 https → 系统（通常是浏览器）
- **抖音、酷安这类靠 App Links 验证直达的不要加规则**，加了会干扰系统自己的路由
- `b23.tv` 这类短链不联网解不开，只能走浏览器；带签名的链接（酷安 `?s=`）绝不能改写 URL
- B 站个人主页（`/space/<mid>`）的 scheme 在部分版本上「接了但什么都不做」，无法探测，所以不加规则、退回浏览器
- 新增 App 时，清单的 `<queries>` 里要补上目标包名，否则 Android 11+ 投递不过去
| 外观面板（头图、标题、配色、GitHub 入口） | `ui/components/AppearanceSheet.kt` |

## 4. 数据与迁移

JSON 版本现在是 **8**，三条 key：

- `ideas_json`：`ideas[]`，每条有 `groupId`
- `groups_json`：`groups[]`，每条有 `name` / `imagePath` / `title`
- `appearance_json`：配色、明暗、自定义状态列表

迁移规则（都在 `JournalJson` 里）：

- v1（`emoji` + `done`）→ 状态；v2（`symbol` / `imagePath`）→ `tint` / `coverPath`
- v5 → v6：按 `ended` 把想法分到「当前 / 已结束」两个固定 id 的组
- v6 → v7：分组增加 `imagePath`、`title`；老版本的全局头图在启动时迁到默认组

**加载时的两道兜底**（重要，别删）：

1. `ideas_json` 解析失败 → 先把原始串存进 `ideas_json_broken`，再落种子，避免覆盖真实数据。
2. 任何 `groupId` 找不到对应组 → 折回第一个组，避免想法永久不可见。

## 5. 发一个新版本（走通过的流程）

1. 改 `app/build.gradle.kts`：`versionCode` +1，`versionName` 改号。
2. `-Task verify` 出包，记下 SHA-256。
3. 更新 README 里的版本号。
4. 提交、打 tag（`v3.7.3` 这种格式）、推送：
   ```powershell
   git add -A
   git commit -m "3.7.4: 改了什么"
   git tag -a v3.7.4 -m "一念 3.7.4"
   git push && git push origin v3.7.4
   ```
5. 建 Release 并挂 APK，两条路都验证过：
   - **网页**（最省事）：Repo → Releases → Draft a new release → 选 tag → 拖 APK → Publish。
   - **API**（可脚本化）：`POST /repos/{owner}/{repo}/releases`，再 `POST https://uploads.github.com/repos/{owner}/{repo}/releases/{id}/assets?name=yinian-3.7.4.apk` 上传文件。

## 6. 踩过的坑（都已验证）

### 构建

- 构建脚本必须由它自己设 `GRADLE_USER_HOME` / `TEMP`，用户目录不可写时会伪装成 JDK、Kotlin、AGP 各种错误。
- `values-night` 里的资源必须在 `values` 有默认值，否则 `lintVitalRelease` 直接失败。
- 加枚举值（例如新的 `StepStatus`）会打断所有 `when`，加值前先 grep 一遍 `when (status)`。

### Compose

- **横向 Pager + 竖向 LazyColumn** 在手势起手时容易抢：给列表一个更大的 `touchSlop`（用 `CompositionLocalProvider(LocalViewConfiguration provides ...)`），横滑更容易被判成翻页。
- **BottomSheet 默认半展开**：所有 `ModalBottomSheet` 都要 `rememberModalBottomSheetState(skipPartiallyExpanded = true)`，否则用户要多拉一次。
- **文字模糊阴影很贵**：卡片标题（blur 12）和小步行（blur 8）是滚动时最大的一笔绘制开销，低端机会掉帧；要压性能就先从这里下手。
- 卡片阴影用三层手绘 `drawRoundRect`（`drawWithCache`），比多层 `graphicsLayer` 便宜得多。
- `LazyColumn` 的 item 一定要用业务 id 做 key，`steps` 用 `id`，`ideas` 用 `id`。

### 网络与 GitHub

- 本机没装 `gh`、也没有 `winget`：推送用 **Git Credential Manager 浏览器授权**，不需要把 token 贴给任何人或写进文件。
- **git 不读系统代理**。浏览器能开 github.com 但 `git push` 报 `Connection was reset`，是因为 Windows 系统代理开着而 git 没继承；按仓库配置 `git config http.proxy` / `https.proxy` 后即通。
- 仓库地址的用户名要核对：截图里看清的是 `cccooo147`（3 个 c、3 个 o），不是 `ccccoo147`，抄错会得到「Repository not found」。

### Release API

- 中文 Release 说明如果直接写在命令行参数里，会被转成 ASCII，页面上全是 `?`。正确做法：**先写进 UTF-8 文件，读成字符串，转成 UTF-8 字节再发**，`Content-Type: application/json; charset=utf-8`。
- `release.upload_url` 里带 `{?name,label}` 模板，PowerShell 里直接拼会报「无效的 URI」；要手动拼 `https://uploads.github.com/repos/{owner}/{repo}/releases/{id}/assets?name=...`。
- 所有 API 请求都要 `Authorization: Bearer <token>`，并且记得带代理参数。

### 仓库卫生

- `keystore.properties` 和 `keystore/` 必须在第一次 commit 之前就进 `.gitignore`；一旦进过历史，删掉也没用。
- PowerShell 的 `git push` 把进度写到 stderr，会出现 `NativeCommandError` 字样，但只要看到 `main -> main` 就是成功了，别被吓到。
- 中文提交信息没问题；中文**命令行参数**有问题（同 Release 那条）。
